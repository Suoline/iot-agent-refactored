## 范围与系统

v4 主实验纳入 10 个无 hidden bridge 的用户可观察场景：H2/C2/B6 及 Q1/U1/R1/D1/S1/V1/E4。legacy 36 场景仅作 Oracle 机制诊断，不进入 v4 Agent 主表。Agent 运行时禁止输入 `memory_ops`、`action_template` 或 evaluator 标签。

主比较为 `Ours` 对 `B0-B5`：B1 为 top-k=5 raw-text RAG，B4 为全部 raw conversation/event history 且不使用 structured MemoryRecord 或 retrieval ranking，B5 仅称 `GA-inspired heuristic`，不是公开 Generative Agents 或 Mem0 实现。

## 指标与统计

主指标只评估用户可观察结局：TSR、Control Final-State TSR、Query Answer Accuracy、Automation Decision Accuracy、Wrong-Device Rate、Unsafe Action Rate、Necessary/Unnecessary Clarification Rate、真实 prompt/completion token 与端到端 latency。`Contract Conformance Score`、SRR、UC、ECE 和机制激活只作诊断。

TSR 只由 action、clarification、final-state、query 外部断言构成；内部 memory assertion 不进入分母。SRR 使用 evaluator-owned lifecycle truth，Context Efficiency 使用真实 trace usage token。transport failure 独立审计并按声明重试，不进入性能分母。provider 不支持 request-level seed 时，`replicate_id` 不是 provider-controlled seed。

统计单位为 scenario × replicate_id 配对观测。二元主指标报告 Ours-minus-baseline paired risk difference 与 scenario/replicate_id two-way pigeonhole clustered bootstrap 95% CI，敏感性分析使用 exact McNemar；本版未实现 clustered GEE，统计工件必须显式记录 `clustered_gee_used=false`。连续指标使用相同两层 clustered bootstrap CI 和 paired sign-flip randomization p 值。Holm family 固定为 Ours 对 B0-B5 的全部预注册 primary metrics；低优指标使用方向归一化 effect，正值始终表示 Ours 更优。

正式 behavioral matrix 的系统边界是 `experiments/` 下的 MemoryService、baseline adapter、plan-only external-LLM Agent 和冻结 HAOracle，不等同于完整 `smartHome/m_agent` 产品运行时。raw-text integrated replay 单独作为端到端 ingestion 证据；在未接入完整产品 runtime 前，不得写成完整 smartHome Agent 验证。

## 正式矩阵

- Agent Behavioral：`7 systems × 10 scenarios × 30 replicate_id = 2100` units。
- Longitudinal：`7 × 1 L1 trajectory × 30 replicate_id = 210` units。
- Robustness：独立 held-out `B6R_v4_robustness` 释义/口语和 `B6W_v4_robustness` 第二家庭 paired subset；跨模型主张仍需第二模型。
- Ingestion：`preference_create`、`preference_conflict_update`，均只接收原始用户文本，并保留 SQLite lineage、检索、动作和真实 usage。后者已有“24 度偏好被自然语言纠正为 26 度并 supersede”的真实 replay；更广泛的自由文本冲突抽取仍属于后续扩展，不能夸大为已验证能力。

机器可读资产位于 `experiments/configs/protocol_v4_formal_*.json`、`experiments/annotations/protocol_v4/annotation_task_pack.json`。提交后必须生成 receipt 并运行 freeze audit，不能将 pre-commit manifest 当作封版证据。重建：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 experiments/scripts/build_protocol_v4_formal_assets.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/scripts/generate_v4_artifacts.py
```

正式运行必须经 `run_strict_group.py --matrix ... --resume --require-agent-backend external_llm` 逐 unit 落盘、预算限制运行，并在每批后执行 trace/strict audit、usage 汇总与统计重建。

启动 30-replicate 正式矩阵前，先完成一个冻结 revision 上的 70-unit preflight（7 systems×10 scenarios×replicate_id 1001）。`audit_protocol_v4_preflight.py` 只有在 70/70、单一 revision、真实 usage、零 transport/fallback、Q1 query metric 和 B1/B4 fidelity 全部通过时才输出 `engineering_ready_for_formal_run`。该 preflight 仍为 `descriptive_only`，不能作为正式显著性结果。

### 临时 LLM-assisted 执行放行

2026-08-14，研究者决定临时接受两个相互隔离的模型标注与第三模型裁决，作为本轮正式矩阵的执行门禁。三份原始文件和机器审计位于 `experiments/annotations/protocol_v4/model_independent/` 与 `experiments/annotations/protocol_v4/llm_assisted_annotation_report.json`。结果为：原始完全一致 `8/13`（61.54%）、schema 归一化后语义一致 `11/13`（84.62%）、model-model Cohen's κ=`0.5455`，裁决分布为 agreement/schema normalization/semantic adjudication=`8/3/2`。

该决定只解除实验执行阻塞，不等同于完成真实人工双标注。readiness 必须显式传入 `--allow-llm-assisted-annotation` 才可接受该报告；报告状态为 `complete_llm_assisted`，并持续记录 `human_annotation_complete=false`、`human_cohen_kappa=null` 和协议偏离。论文若使用由此启动的结果，必须披露标注来源，不能称为 human Cohen's κ；后续真实人工复核仍需补齐。

`analyze_protocol_v4_formal.py` 只有在冻结的 2100-unit behavioral matrix 被完整、无额外 unit 地覆盖时，才会输出 `formal_analysis_ready`；其他任何样本量均为 `descriptive_only`。
