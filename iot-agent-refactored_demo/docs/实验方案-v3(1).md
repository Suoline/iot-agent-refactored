## 1. Overview

This document is the experimental design + concrete test suite for validating the
**Structured Memory + Lifecycle Closure** architecture (v4) for smart-home agents. The core
contributions under test:

1. **Memory expiration** — half-life decay, hard/window expiry, lifecycle state machine (v4 §5)
2. **Memory update operations** — the full set add/merge/revise/invalidate/split/delete with
   provenance and coverage_proof (v4 §7)
3. **Confidence calibration** — asymmetric feedback, Memory Worth tiers, usage thresholds (v4 §6)
4. **Dead-memory governance** — dual-branch detection (resample vs age-out) + resampling (v4 §12.1)
5. **Retrieval/planning gating** — candidate isolation, registry authority, ambiguity gate (v4 §8, §11)

Peer-review targets:
- Pre-registered metrics with explicit formulas over named trace fields (§8)
- Ablations isolating each mechanism's marginal contribution (§7)
- A baseline ladder from stateless to large-context to a published-system analog (§6)
- An auditable claim↔scenario↔RQ↔metric coverage matrix with zero uncovered v4 claims (§14)
- Fully specified, frozen, dual-annotated deterministic test scripts (§5)

---

## 2. Core Research Questions

**RQ1 — Memory Expiration.** Does time-aware management (decay + hard expiry + window
validity) reduce stale recall and preserve task success vs systems without expiration?

**RQ2 — Memory Update.** Do structured update operations (merge/revise/invalidate/split/delete)
maintain memory consistency and provenance better than naive overwrite?

**RQ3 — Confidence Calibration.** Does asymmetric execution feedback + Memory Worth tiers +
usage thresholds improve reliability and reduce clarification overhead?

**RQ4 — Dead-Memory Governance.** Does dual-branch dead-memory detection + resampling improve
storage efficiency and retrieval precision without losing valuable information?

**RQ5 — End-to-End Performance & Cost.** Does the integrated system beat baselines on task
success and the operational proxies for user satisfaction (clarification burden, unsafe-action
avoidance, preference match) **at acceptable context cost** — i.e. not merely by spending more
tokens than a large-context baseline?

> RQ5 is not a human study; N≥30/20 runs are LLM-sampling repetitions. "User satisfaction" is
> operationalized as the three computable proxies in §6.4 (CB, UAA, PM).

---

## 3. Scenario Design Dimensions

**Temporal dynamics:** Static (capabilities, layout) · Evolving (preferences, nicknames) ·
Episodic (task outcomes, temporary rules).

**Ambiguity level:** Unambiguous ("Turn on bedroom ceiling light") · Moderate ("Turn on the
small lamp", alias resolution) · High ("Turn on the light", needs room/time/usage context).

**Polarity:** Positive (system should act/recall) · Negative (system should stay silent, ask,
or refuse to fabricate). Category G and the negative arms of A/C/H test polarity explicitly.

## 5. Test Suite — 36 Deterministic Scenario Scripts

### 5.1 Script format

Each scenario is a frozen ordered list of steps. Every step is one of:

- **`say`** — a user utterance at `t` (relative to scenario start t0).
- **`event`** — a world mutation / failure injection fires (from §4.4) or a clock advance.
- **`expect_action`** — ground-truth action the system should emit (`{service, entity, args}`),
  or `∅` for correct silence.
- **`expect_clarify`** — ground truth is a clarification question (negative/ambiguous polarity).
- **`expect_memory`** — asserted ground-truth memory state after the step: memory_type, key
  fields, and lifecycle `status` (this feeds SRR/UC/DMR scoring, independent of what the system
  self-reports).

Fields used by scoring: `expect_action`↔TSR/WDR/PM, `expect_clarify`↔CB/CE, `expect_memory.status`
↔SRR/UC, safety flag↔UAA. `RQ` and `Planner` (oracle for RQ1–RQ4, agent for RQ5, per §9) tag
each scenario. Time notation `t0+Nd HH:MM` uses the simulated clock (§10 harness).

Each scenario is dual-annotated; disagreements go to a third annotator; Cohen's κ reported (§12).

### Category A — Alias Evolution & Governance (6) — RQ1, RQ2, RQ3, RQ4

**A1 — Alias commit + recall.** *(Planner: oracle; RQ3)*
1. `say` t0 09:00 "以后把书房台灯叫小书灯" → `expect_memory`: alias(小书灯→`light.study_desk`),
   source=user_explicit, status=**active**, conf=0.90.
2. `say` t0+1d 20:00 "打开小书灯" → `expect_action` `light.turn_on(light.study_desk)`;
   `expect_memory`: same alias positive_hits=1.
- Checks: explicit alias → immediate active (v4 §11), correct recall, positive hit reinforcement.

**A2 — Alias reassignment / supersession.** *(oracle; RQ2)*
1. `say` t0 "卧室灯就是卧室顶灯" → alias(卧室灯→`light.bedroom_ceiling`) active.
2. `say` t0+3d "以后卧室灯指床头灯" → `expect_memory`: old alias status=**superseded**,
   superseded_by=new; new alias(卧室灯→`light.bedroom_bedside`) active, conf=0.95.
3. `say` t0+3d "开卧室灯" → `expect_action` `light.turn_on(light.bedroom_bedside)`.
- Checks: revise/supersede, provenance chain, no stale recall of old binding. (UC scenario.)

**A3 — Competing aliases, confidence disambiguation.** *(oracle; RQ3)*
1. `say` t0 "书房台灯叫小书灯" → alias A active (conf 0.90).
2. `event` t0+1d: behavior-inferred alias B ("台灯"→`light.study_ceiling`) written as
   candidate (source=user_behavior, conf 0.65, status=**candidate**).
3. `say` t0+2d "开台灯" → top1 (A, active) vs candidate B: candidate excluded from usable set;
   if residual ambiguity margin < threshold `expect_clarify`, else `expect_action` on A.
- Checks: candidate isolation (§11), ambiguity gate (§8.1 step 7).

**A4 — Dead-memory: fuzzy-text → resample.** *(oracle; RQ4)*
1. `event` t0: seed alias(小书灯→`light.study_desk`) created, natural_text deliberately vague
   ("那个灯"), access_count=0, half_life=365d.
2. `event` t0+400d: maintenance runs → `is_dead` true (access_count==0 ∧ age>half_life).
   Diagnosis: text fuzzy (high embedding entropy) → **resample** branch: LLM rewrites
   natural_text to specific form, resampled=True, last_accessed reset.
3. `say` t0+401d "开小书灯" → `expect_action` on `light.study_desk`; `expect_memory`: status
   back to **active** (revived). RRR credit.
- Checks: §12.1 branch-2 resample, RRR.

**A5 — User correction → negative hit + reflection.** *(oracle; RQ2, RQ3)*
1. `say` t0 "开小书灯" (alias already active) → action on `light.study_desk`.
2. `say` t0 "不对，不是这个灯，是书房顶灯" → `expect_memory`: alias(小书灯) negative_hits+1,
   conf drops (α_neg=0.20), status→**stale/conflicted**; new corrected alias or reflection
   written (failure_type=wrong_device). Next recall must prefer corrected target.
- Checks: asymmetric negative feedback (§6.2), reflection (§10.2). (UC scenario.)

**A6 — Dead-memory: non-fuzzy aging → stale→archived.** *(oracle; RQ4) — new in v3, complements A4*
1. `event` t0: seed alias(客厅落地灯→`light.living_floor`), natural_text already specific,
   access_count=0, half_life=365d.
2. `event` t0+400d: maintenance → `is_dead` true. Diagnosis: text NOT fuzzy → **content-aging**
   branch (§12.1 step 3): status active→**stale**→**archived**; MW low → cleanup candidate.
3. `say` t0+401d "开客厅落地灯" → recall from archived is allowed to miss; `expect_action` falls
   back to HA registry match (device still exists) — verifies archived does not block, and aging
   ≠ resample. `expect_memory`: alias status=**archived** (not resampled).
- Checks: §12.1 branch-3 aging, distinct from A4; DMR.

### Category B — Preference & Habit Formation (6) — RQ1, RQ3

**B1 — Single observation stays candidate.** *(oracle; RQ3)*
1. `event` t0 20:00: observe user set `climate.bedroom_ac` to 24°C once → habit candidate,
   status=**candidate**, source=user_behavior.
2. `say` t0+1d "睡觉了" (sleep routine) → `expect_action` must NOT auto-apply 24°C (candidate
   not usable). `expect_memory`: candidate unchanged.
- Checks: candidate isolation prevents premature automation (§11).

**B2 — 3× in 7 days → habit promoted.** *(oracle; RQ3)*
1. `event` t0/t0+2d/t0+4d 20:00: same 24°C behavior ×3, no counter-example.
2. `event` t0+4d maintenance → habit(卧室睡前24°C) candidate→**active** (7d/3× rule, §11).
3. `say` t0+5d "睡觉了" → `expect_action` includes `climate.set_temperature(bedroom_ac,24)`.
- Checks: promotion gate threshold.

**B3 — Explicit statement → immediate active.** *(oracle; RQ3)*
1. `say` t0 "我睡觉时喜欢空调26度" → preference active immediately (conf 0.90, source explicit).
2. `say` t0 "睡觉了" → `expect_action` set_temp 26.
- Checks: explicit > behavior promotion path.

**B4 — Preference revocation.** *(oracle; RQ1)*
1. `say` t0 "睡觉时把空调设成26度" → pref active.
2. `say` t0+3d "以后睡觉别自动调空调了" → `expect_memory`: pref status=**superseded/expired**.
3. `say` t0+3d "睡觉了" → `expect_action` must NOT set temperature. (Negative-action check.)
- Checks: window/explicit invalidation removes planning influence. (UC scenario.)

**B5 — Long-term contradictory behavior → habit decays/superseded.** *(oracle; RQ1)*
1. `event` t0: habit(睡前24°C) active.
2. `event` t0+1d..t0+10d: 5 observations of user setting 27°C instead.
3. `event` t0+10d maintenance → old habit conflicted→superseded by new habit(27°C).
4. `say` t0+11d "睡觉了" → `expect_action` set_temp 27.
- Checks: behavior-driven supersession, decay under contradiction.

**B6 — High-MW preference used in high-risk task.** *(agent; RQ3)*
1. `event` t0: preference(睡前锁大门) with MW>0.8 (positive_hits≫, conf>0.85), source explicit
   + many verified executions.
2. `say` t0+30d "睡觉了" → safety-relevant lock action. Per §6.3 MW>0.8 "可在高风险场景直接使用":
   `expect_action` `lock.lock(front_door)` **without** an extra clarification, while a fresh
   low-MW preference (control arm) would require confirmation.
- Checks: MW tier actually changes gating behavior (not just bookkeeping). Compare CB vs control arm.

### Category C — Temporary Rules & Time-Window Validity (4) — RQ1, RQ3

**C1 — One-week temporary rule expires.** *(oracle; RQ1)*
1. `say` t0 "这周客厅灯晚上7点自动开" → rule with valid_until=t0+7d, status active.
2. `event` t0+3d 19:00 → `expect_action` `light.turn_on(living_ceiling)` (within window).
3. `event` t0+9d 19:00 → `expect_action` ∅; `expect_memory`: rule status=**expired**
   (valid_until passed). No execution after expiry.
- Checks: `valid_until` hard-window enforcement.

**C2 — Holiday automation with explicit date range.** *(oracle; RQ1)*
1. `say` t0 "国庆假期(t0+10d 到 t0+17d)每晚开氛围灯" → rule valid_from/valid_until set.
2. `event` t0+5d 20:00 → ∅ (before window). `event` t0+12d 20:00 → action on `living_ambient`.
   `event` t0+20d 20:00 → ∅, status expired.
- Checks: valid_from AND valid_until, both edges.

**C3 — Soft expiration via confidence decay.** *(oracle; RQ1)*
1. `event` t0: preference(low importance) conf 0.72, half_life 90d.
2. `event` t0+180d: effective_confidence = 0.72·2^(-2)≈0.18 < control threshold 0.70.
3. `say` t0+181d relevant task → `expect_clarify` (below threshold) rather than silent use;
   `expect_memory`: status active→**stale** (eff_conf<0.45).
- Checks: soft expiration through `effective_confidence` (§5.2), threshold gating (§6.4).

**C4 — needs_verification (MW 0.2–0.4) cross-check before use.** *(oracle; RQ1, RQ3)*
1. `event` t0: memory with MW in 0.2–0.4 (negative_hits high) → tagged `needs_verification`.
2. `say` t0+1d task depending on it → `expect_clarify`/cross-check, NOT silent execution.
- Checks: §6.3 suspicious tier behavior.

### Category D — Device Registry Changes (3) — RQ1, RQ2

**D1 — Device removed → hard expiry.** *(oracle; RQ1, RQ2)*
1. `event` t0: alias/location memories for `switch.study_heater` active.
2. `event` t0+5d 09:00 `evt_dev_removed` → maintenance marks all `switch.study_heater`
   memories **expired** (HA registry authority, §5 hard-expire).
3. `say` t0+5d "开书房小太阳" → `expect_clarify`/inform-not-found; `expect_action` ∅ (device gone).
- Checks: registry-driven hard expiration cascades to alias/location.

**D2 — Capability changed → dependent routine stale.** *(oracle; RQ2)*
1. `event` t0: routine referencing `light.living_ceiling` color_temp active.
2. `event` t0+6d `evt_cap_changed` (loses color_temp) → dependent routine downgraded to
   **stale** (§7.4 cascade).
3. `say` t0+6d trigger routine → `expect_action` executes only still-valid steps / clarifies on

- Checks: capability-change cascade to routine.

**D3 — Sensor relocated → cascade update.** *(oracle; RQ1, RQ2)*
1. `event` t0: layout_relation(`sensor.hall_motion` in hall) + a hall motion→light routine.
2. `event` t0+7d `evt_sensor_moved` (hall→living) → layout_relation revised, dependent room
   clue/routine re-evaluated (§7.4).
3. `say`/`event` t0+7d motion trigger → `expect_action` reflects new room binding, old hall
   binding status=**superseded**.
- Checks: relocation cascade across layout_relation + routine.

### Category E — Routine & Composite Task Planning (3) — RQ3, RQ5

**E1 — 观影模式 composite.** *(agent; RQ5)*
1. `say` t0 "定义观影模式：关客厅顶灯、开氛围灯、关窗帘" → routine(观影模式) active with 3 steps.
2. `say` t0+1d "观影模式" → `expect_action` sequence: `light.turn_off(living_ceiling)`,
   `light.turn_on(living_ambient)`, `cover.set_position(living_curtain,0)`.
- Checks: multi-step routine planning + grounding.

**E2 — Routine with safety action needs confirmation.** *(agent; RQ5)*
1. `say` t0 "睡前模式：关全屋灯并锁大门" → routine active; lock step is safety-relevant.
2. `say` t0+1d "睡前模式" → `expect_action` on lights, and lock step gated: `expect_clarify`
   confirm before `lock.lock` (safety threshold 0.85, §6.4). safety_gated=true. (UAA scenario.)
- Checks: safety-tier confirmation gating.

**E3 — Failure → reflection → next plan avoids path.** *(agent; RQ3, RQ5)*
1. `say` t0+2d 22:00 "睡前模式" → `event` `evt_lock_jam` fires → `lock.lock` returns jammed;
   outcome=failure; `expect_memory`: reflection written (failure_type=service_failure,
   future_rule=检查锁芯/改提示), episode negative_hits on the lock step.
2. `say` t0+2d 22:05 "睡前模式" again → `expect_action`: lights execute, lock step now warns /
   suggests manual instead of blindly retrying (reflection used).
- Checks: execution closure — reflection avoids repeated failed path (§10.2). Ripple isolation
  (only lock step penalized, lights untouched) cross-checked with F3/F4.

### Category F — Conflict, Cascade, Merge, Split & Delete (7) — RQ2, RQ4

**F1 — Feature-absorption warning → specialize (rejected merge).** *(oracle; RQ2)*
1. `event` t0: alias(客厅灯→`light.living_floor`) and fact(客厅顶灯→`light.living_ceiling`).
2. `event` t0+1d maintenance attempts merge (subject overlap 客厅灯 ⊃ 客厅顶灯) → §7.3 triggers
   **feature-absorption warning**: NOT merged; instead `MemoryEdge` specializes/generalizes created.
   `expect_memory`: both records survive, edge exists, no merged record.
- Checks: absorption warning, specialize edge. (Negative merge branch.)

**F2 — Two high-confidence facts conflict → conflicted + clarify.** *(oracle; RQ2)*
1. `say` t0 "小书灯是书房台灯" (conf 0.90).
2. `say` t0+1d (different session) "小书灯是书房顶灯" (conf 0.90) → §7.2 two high-conf conflict →
   `expect_memory`: both status=**conflicted**.
3. `say` t0+1d "开小书灯" → `expect_clarify` (which one).
- Checks: conflict closure, conflicted-status clarification.

**F3 — Negative ripple propagation.** *(oracle; RQ4)*
1. `event` t0: memory graph — episode(lock task) —edge dist1→ location(hall) —edge dist2→
   layout_relation. All active.
2. `event` t0+2d `evt_lock_jam` → lock task fails → direct_penalty on episode; propagated
   penalty = direct·0.3^d for d≤2. `expect_memory`: dist-1 penalized 0.3×, dist-2 0.09×,
   dist-3 (a decoy edge) **unchanged**.
- Checks: ripple decay 0.3^d, max_distance=2 (§7.4).

**F4 — Positive hits do NOT propagate (isolation).** *(oracle; RQ4)*
1. Same graph, but t0+2d lock task **succeeds** → positive_hits+1 on the used episode only.
2. `expect_memory`: neighbor memories (dist 1,2) positive_hits unchanged.
- Checks: positive isolation — success does not pollute neighborhood (§7.4). Paired with F3.

**F5 — Over-broad memory → split.** *(oracle; RQ2)*
1. `event` t0: single over-broad alias(客厅灯→matches living_ceiling ∨ living_ambient ∨
   living_floor), causing repeated partial matches / ambiguity.
2. `event` t0+1d maintenance detects frequent partial-match → **split** into finer records
   (per-entity) with specialize edges. `expect_memory`: original superseded, ≥2 finer records active.
3. `say` t0+1d "开客厅顶灯" → `expect_action` resolves cleanly to `light.living_ceiling`.
- Checks: §7 `split` operation (partial-match rate drops post-split).

**F6 — Successful merge + coverage_proof + rollback.** *(oracle; RQ2) — new in v3*
1. `event` t0: two records, object **fully equivalent** (alias 小书灯→study_desk from two
   sessions) → §7.3 allows merge. `expect_memory`: single merged record, `merged_from`=[both],
   `coverage_proof` recorded, evidence_refs union preserved.
2. `event` t0+1d: inject a merge that **omits** coverage_proof → maintenance job (§7.3
   "否则回滚此次合并") **rolls it back**. `expect_memory`: the bad merge reverted to two records.
- Checks: positive merge path + coverage_proof + rollback (only F1's negative branch existed before).

**F7 — Privacy delete.** *(oracle; RQ2) — new in v3*
1. `say` t0 "记住我常去健身房" → preference active (+ embedding indexed).
2. `say` t0+2d "把我去健身房这件事忘掉" → `delete` op (§7): logical delete, removed from Chroma
   index. `expect_memory`: status=**deleted**, audit event retained (memory_events.jsonl).
3. `say` t0+2d query that would have recalled it → `expect_action` ∅ / no recall; must not
   resurface deleted content.
- Checks: `delete` operation (the last untested update op) + index removal + non-resurfacing.
  Also exercises the §12.1 `sensitive=true → needs_review` path if flagged sensitive.

### Category G — Negative Controls & Cold Start (5) — RQ1, RQ4, RQ5

**G1 — Cold start, no fabrication.** *(agent; RQ5)*
1. Empty memory store. `say` t0 "开卧室灯" → two bedroom lights exist, no alias. `expect_clarify`
   (which light) OR registry-default per policy; must NOT invent an alias/preference.
- Checks: no hallucinated recall from empty memory.

**G2 — Distractor robustness.** *(oracle; RQ1, RQ4)*
1. `event` t0: seed 8 irrelevant memories (other rooms, unrelated prefs), semantically near.
2. `say` t0+1d "开书房台灯" → `expect_action` `light.turn_on(study_desk)`; distractors must NOT
   enter grounding set / derail selection.
- Checks: retrieval precision under distractors (SRR/WDR should not degrade).

**G3 — Registry overrides stale memory.** *(oracle; RQ1)*
1. `event` t0: stored fact "客厅顶灯支持 color_temp" active.
2. `event` t0+6d `evt_cap_changed` (color_temp removed) but stored fact not yet self-updated.
3. `say` t0+6d "把客厅顶灯调成暖色" → HA registry (authority, §7.2) wins: `expect_clarify`/
   inform capability unavailable; stored stale fact must NOT override live registry.
- Checks: registry authority beats stale memory.

**G4 — Low-confidence non-execution.** *(oracle; RQ3)*
1. `event` t0: llm_inference candidate (conf 0.45) about a device binding.
2. `say` t0 control task depending on it → below 0.70 control threshold → `expect_clarify`,
   not silent execution.
- Checks: usage threshold + candidate isolation.

**G5 — Transient state must not be persisted.** *(oracle; RQ1, RQ4) — new in v3*
1. `event` t0 20:00: observe `light.living_ceiling` is currently on (ha_state_observation).
2. `event` t0+1d maintenance → `expect_memory`: NO long-term MemoryRecord created for the
   transient on-state (v4 §3 principle: 当前状态不进入长期记忆; only perception).
3. `say` t0+2d 09:00 "客厅灯之前是不是开着" → system may answer from short-term perception if
   available, but must NOT have a persisted `stable_state_fact` claiming it is on, and must NOT
   plan future actions assuming it is on. `expect_memory`: no persisted state fact.
- Checks: the core "current state ≠ memory" principle has an explicit negative control.

### Category H — Query-Type Tasks & Threshold Tiers (2) — RQ3 — new in v3

Covers the query tier (0.45 threshold, §6.4) that had no scenario in v2.

**H1 — Query task at 0.45 tier tolerates lower confidence.** *(oracle; RQ3)*

2. `say` t0+1d "卧室空调设的多少度" (query, not control) → threshold 0.45 → `expect_action`:

**H2 — Query vs control tier boundary contrast.** *(oracle; RQ3)*

## 6. Baselines

| ID | Baseline | Description | Answers |
| --- | --- | --- | --- |
| **B0** | Stateless | No memory; each turn = current utterance + HA registry only. | value of any memory |
| **B1** | RAG-only (top-k) | Vector store of past utterances; top-k retrieval, no structure/lifecycle. | value of structure |
| **B2** | Structured, no lifecycle | Structured fact tuples, always-active; no expiry/confidence/governance. | value of lifecycle |
| **B3** | Structured + static confidence | Source-prior confidence, no decay, no feedback updates. | value of dynamic conf |
| **B4** *(new)* | Full-history / large-context | Entire interaction history stuffed into the planner prompt, **no retrieval, no structure**. Grows unbounded. | "just more context?" |
| **B5** *(new)* | Published-system analog | Generative-Agents-style scored retrieval (recency + importance + relevance), no lifecycle/expiry/governance. Represents Mem0/GA-class prior work. | vs real prior art |
| **Ours** | SAE Memory v4 | Full: structure + lifecycle + asymmetric feedback + governance. | — |

**Why B4 is required.** §6.3 / Table 4 / §13 all claim Ours does not merely win by spending
more tokens. That claim is only falsifiable against a large-context control. B4 is that control:
if Ours matches or beats B4's TSR at far fewer `prompt_tokens`, the memory structure is doing
real work, not the token budget. B4 also stress-tests scaling (its prompt grows with history;
Context Efficiency should collapse over simulated time).

**Why B5 is required.** B0–B3 are internally-constructed ladders; a reviewer will ask why we
don't compare to published memory systems. B5 approximates the Generative-Agents retrieval score
(and stands in for Mem0-class extract-merge memory) so Ours' deltas are measured against prior
art, not only against straw men.

> All baselines run under the **same planner mode** (§9), **same frozen `wm-v1`** (§4), same
> LLM/temperature, same embedding model, same scenario scripts and clock. Only the memory
> subsystem differs. B4 differs only in feeding raw history instead of a retrieved package.

## 8. Evaluation Metrics

> **Principle: every metric is pre-registered as a formula over named trace fields (§11).** The
> three v1 ambiguities (SRR denominator, CE weighting, MP "helpful" judge) remain resolved as in v2.

### 8.1 Primary metrics (N≥30)

| Metric | Definition | Dir |
| --- | --- | --- |
| **TSR** | Fraction of tasks whose final device state == ground-truth intent | ↑ |
| **SRR** | Fraction of retrieval steps whose usable set contains an expired/superseded memory | ↓ |
| **WDR** | Fraction of control tasks routed to the wrong entity | ↓ |
| **CE** | Clarification reduction normalized by accuracy retention (formula §8.5) | ↑ |
| **UC** | After a correction, fraction where old memory invalidated ∧ new used | ↑ |

### 8.2 Calibration & governance (N≥20)

| Metric | Definition | Dir |
| --- | --- | --- |
| **ECE** | Expected calibration error, predicted eff_conf vs actual success (M=10 bins) | ↓ |
| **DMR** | Fraction of memories unaccessed past half-life | ↓ |
| **RRR** | Fraction of resampled memories recalled next cycle | ↑ |
| **MP** | Fraction of committed memories later used helpfully (deterministic rule §8.5) | ↑ |

### 8.3 Cost & efficiency (per task, aggregated per system)

| Metric | Definition | Dir |
| --- | --- | --- |
| **End-to-end Latency** | utterance → action decision (ms) | ↓ |
| **Retrieval Latency** | time in retrieval stage (ms) | ↓ |
| **Maintenance Cost** | time + tokens of maintenance job per simulated day | ↓ |
| **Prompt Token Count** | tokens fed to planner LLM per task | ↓ |
| **Active Memory Count** | active/stale retrievable population over time | — |
| **Context Efficiency** | TSR ÷ mean prompt_tokens × 1000 | ↑ |

> Context Efficiency is the headline for the B4 comparison: match B4's TSR at far fewer tokens ⇒
> structure, not budget, is doing the work.

### 8.4 RQ5 user-satisfaction proxies

| Proxy | Definition | Source | Dir |
| --- | --- | --- | --- |
| **Clarification Burden (CB)** | mean clarification turns/task | trace `clarification_turns` | ↓ |
| **Unsafe-Action Avoidance (UAA)** | fraction of safety tasks where sub-0.85 action was gated | safety log | ↑ |
| **Preference Match (PM)** | fraction whose chosen action matches annotated preference | scenario GT | ↑ |

### 8.5 Operationalization (formulas over §11 trace)

Notation: run → tasks `t∈T`; task → retrieval steps `s∈S_t`; step returns usable set `R_s`
(status ∈ {active, usable-stale}).

- **TSR** = `(1/|T|)·Σ_t 1[final_device_state(t)==ground_truth_state(t)]`, exact match on annotated targets.
- **SRR** = `Σ_t Σ_{s} 1[∃ m∈R_s : true_status(m,t)∈{expired,superseded}] / Σ_t |S_t|`.
  `true_status` from simulated clock + `expect_memory` annotation, independent of system self-report.
- **WDR** over control tasks `T_ctrl`: `(1/|T_ctrl|)·Σ 1[chosen_entity≠ground_truth_entity]`.
- **CE** = `(CB_B0 − CB_sys)/CB_B0 · (acc_sys/acc_B0)`. First factor = relative clarification
  reduction vs stateless B0; second = accuracy retention. CE>0 ⇒ fewer questions without accuracy
  loss. If B0 never clarifies, use B1 as reference and report which.
- **UC** over correction tasks (A2, A5, B4, D-series): fraction where `old.status∈{superseded,
  expired} ∧ new_memory∈R_s` of the post-correction task.
- **ECE** = `Σ_b (|B_b|/n)·|acc(B_b)−conf(B_b)|`, bins over top-1 used memory's eff_conf vs binary success.
- **DMR** = `#(access_count==0 ∧ age_days>half_life)/#total` at end of run (matches §12.1 is_dead).
- **RRR** = `#(resampled memories recalled into an active set within next maintenance cycle)/#resampled`.
- **MP**: a committed memory is *helpful* iff it is in `R_s` of a task with
  `MemoryUsageEvent.contribution=="helpful"` AND `outcome=="success"`. `contribution` set by the
  deterministic usage-tracker (NOT an LLM): `helpful` iff in the chosen plan's grounding set and
  verified state matched intent; `misleading` iff in grounding set and verification failed on the
  grounded attribute; `neutral` otherwise. `MP = #helpful / #committed`.
- **Cost**: read `*_latency_ms`, `prompt_tokens`, maintenance log directly.
- **RQ5 proxies**: CB from `clarification_turns`; UAA from `safety_gated==true` on safety tasks;
  PM from `chosen_action` vs annotated `preferred_action`.

### 8.6 Statistical protocol

- **Primary metrics (§8.1): N≥30** runs/scenario (distinct seeds). **Secondary (§8.2–8.4): N≥20.**
  Higher N on primary metrics so the multiple-comparison correction does not crush true small effects.
- Report **mean ± 95% CI**; paired bootstrap or Wilcoxon signed-rank for system comparisons.
- Pre-declare a **primary vs secondary metric tier**; apply **Holm correction within tier** rather
  than one flat Bonferroni across all ~16 metrics (which would over-penalize).
- Report **effect sizes (Cohen's d)**, not only p-values.
- Freeze all §8.5 formulas before the full suite runs (metric-gaming mitigation).

## 9. Planner Mode: Oracle vs Agent

**Problem.** TSR is jointly determined by (a) the memory subsystem and (b) the planner's
reasoning. Holding the LLM constant controls cross-system fairness but does not stop planner
noise from swamping the memory signal.

**Solution.** Two planner modes; each scenario runs under the mode tagged in §5.

| Mode | Planner | Measures | Used for |
| --- | --- | --- | --- |
| **Oracle** | Deterministic rule-based planner over the §8.3-v4 retrieval package; given correct memories it always plans correctly; no free-form LLM. Planner noise = 0. | Pure memory quality: recall, disambiguation, state update, expiry. | RQ1–RQ4 (primary attribution) |
| **Agent** | Full LLM planner (free-form over the same package). | End-to-end behavior under realistic noise. | RQ5 (end-to-end) |

**Oracle planner contract** (deterministic, no sampling):
- Input: §8.3-v4 package (`candidate_devices`, `global_constraints`, `should_ask_user`, thresholds).
- Rule: pick top-1 candidate if `score` clears the §6.4-v4 task threshold AND top1–top2 gap
  exceeds the ambiguity margin; else clarify; apply `global_constraints` as hard filters; never
  invent entities outside the package. Fully reproducible given the package.

**Cost / priority.** The faithful oracle planner is the heaviest single item. RQ1–RQ4 can first
be reported under the agent planner (N≥30 averages noise); the oracle run is the *cleaner
confirmatory* result that removes "is it the LLM or the memory?" — strongly recommended for
camera-ready, not a blocker (Phase 8).

## 10. World Model & HA Oracle Protocol

The World Model is a **frozen versioned artifact** (`wm-v1`, §4). All systems load the identical
world. Contents = §4 (rooms, entities, capabilities, service schema, scheduled mutations,
failure injections). Deterministic interface:

```text
world.get_registry(t)        # authoritative device/entity/capability snapshot at sim-time t
world.get_state(entity, t)   # current state (perception only; NOT long-term memory)
world.apply(service,args,t)  # (success|failure, state_delta) via transition + injected failures
world.events_between(t0,t1)  # registry mutations + scheduled failures in window
```

The registry is the **authority** for device existence, entity binding, and service schema (v4
§7.2). G3 is scored against this. `simulated_clock.py` advances virtual time so half-life/expiry
fire instantly. World serialized to `world_model/v1.json`, version-pinned, `world_version` logged
in every trace; a scenario may only reference entities present in its pinned world.

## 11. Execution Trace Schema

Per task and per retrieval step; single source for every §8.5 metric. Dynamic per-memory values
nested in `retrieved_memories[]`.

```python
class RetrievedMemory(BaseModel):
    memory_id: str
    memory_type: str
    rank: int
    retrieval_score: float             # v4 §8.2 composite
    effective_confidence: float        # v4 §5.2, recomputed at retrieval time
    memory_worth: float                # v4 §6.3
    raw_confidence: float
    system_status: str                 # status the SYSTEM assigned
    true_status: str                   # GROUND-TRUTH status at sim-time (for SRR)
    in_usable_set: bool                # passed StatusFilter → planner may use
    in_grounding_set: bool             # actually used to ground the chosen action

class RetrievalStep(BaseModel):
    step_id: str
    stage: Literal["device_filter","constraint_filter","planning","execution","verification"]
    query: str
    retrieved_memories: list[RetrievedMemory]
    retrieval_latency_ms: float

class TaskTrace(BaseModel):
    task_id: str
    scenario_id: str
    seed: int
    world_version: str                 # pinned world (wm-v1)
    planner_mode: Literal["oracle","agent"]
    sim_time: datetime
    system_id: str                     # B0..B5 / Ours / ablation id
    steps: list[RetrievalStep]
    chosen_action: dict | None         # {service, entity_id, args} or None
    clarification_turns: int
    should_ask_user: bool
    final_device_state: dict           # TSR
    ground_truth_state: dict
    ground_truth_entity: str | None    # WDR
    preferred_action: dict | None      # PM (RQ5)
    usage_events: list[dict]           # v4 §10.1 MemoryUsageEvent
    memory_status_after: dict          # {memory_id: status} post-task (UC)
    outcome: Literal["success","partial_success","failure"]
    end_to_end_latency_ms: float
    prompt_tokens: int
    safety_relevant: bool
    safety_gated: bool                 # confirmation correctly required (UAA)
```

Metric mapping: TSR↔`final_device_state/ground_truth_state`; SRR↔`RetrievedMemory.true_status`
over usable sets; WDR↔`chosen_action.entity_id/ground_truth_entity`; CE/CB↔`clarification_turns`
+TSR; UC↔`memory_status_after`+post-correction `in_usable_set`; ECE↔top-1 `effective_confidence`
+`outcome`; MP↔`usage_events.contribution`+`outcome`; cost↔`*_latency_ms`/`prompt_tokens`;
UAA↔`safety_gated`; PM↔`preferred_action`.
